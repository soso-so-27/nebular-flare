## 1. エラー / エッジケース方針

### 1-1. エラー対応の原則

1. **技術用語を見せない**: エラーコードやスタックトレースは絶対にユーザーに表示しない
2. **次にできることを伝える**: エラーだけ伝えて終わりにしない。リカバリ手段を示す
3. **データを失わない**: エラー時も入力済みデータを可能な限り保持する
4. **静かに再試行**: ネットワークエラーは3回まで自動リトライしてからユーザーに通知

### 1-2. エラーパターン別の対応

#### ネットワークエラー

```
状況: API呼び出し失敗、Supabase接続断
表示: 「つながりにくいようです」
アクション: [もう一度試す] ボタン
裏側: 3回自動リトライ後にユーザー通知。React Query の retry: 3 で対応
保護: 入力中のデータは localStorage に一時保存
```

#### 写真アップロード失敗

```
状況: 画像圧縮エラー、ストレージ容量超過、タイムアウト
表示: 「○枚の写真はうまく読み込めませんでした」
アクション: [あとでもう一度試す] / [スキップして続ける]
裏側: 成功分は保持。失敗分のみリトライキューに入れる
保護: 全体のインポートは失敗分があっても中断しない
```

#### AI解析失敗

```
状況: OpenAI API エラー、タイムアウト、レート制限
表示: （表示しない。写真は「解析待ち」状態のまま）
アクション: バックグラウンドで自動リトライ（指数バックオフ）
裏側: photo_analysis_jobs.status = 'failed' → 次回ワーカー起動時にリトライ
保護: 解析なしでも写真は図鑑に表示される（タグなし状態）
```

#### 認証エラー

```
状況: セッション期限切れ、トークン無効
表示: 「もう一度ログインしてください」
アクション: ログイン画面に遷移
裏側: Supabase の onAuthStateChange で検知。ローカルデータは保持
保護: 未送信のケア記録等は localStorage に保持し、ログイン後に送信
```

#### ストレージ容量超過

```
状況: Supabase Storage の上限に接近
表示: 「写真の保存スペースが少なくなっています」
アクション: [古い写真を整理する] / [にゃるほどプラスにアップグレード]
裏側: ストレージ使用量をプロフィールに保持し、80%で警告
```

### 1-3. 空状態（Empty State）のデザイン

空状態はエラーではなく「始まりの招待」として設計する。

| 画面 | 空状態メッセージ | アクション |
|------|---------------|-----------|
| ホーム（写真なし） | 「最初の一枚を撮ってみましょう」 | [📷 撮影する] ボタン |
| 図鑑（エントリなし） | 「写真が増えると、図鑑が育ちます」 | [写真を追加] ボタン |
| カレンダー（記録なし） | 「まだ何も記録がない日です」 | [ケアを記録] / [写真を追加] |
| 猫プロフィール（猫なし） | 「あなたの猫を教えてください」 | [猫を登録] ボタン |
| 発見（発見なし） | 「写真を追加するほど、発見が増えます」 | なし（自然に待つ） |
| 検索結果なし | 「見つかりませんでした」 | [条件を変えて探す] |

### 1-4. ローディング状態

```
短時間（〜1秒）:  何も表示しない（ちらつき防止）
中時間（1〜3秒）: スケルトンスクリーン（写真グリッドのプレースホルダー）
長時間（3秒〜）:  プログレス表示（「猫を見つけています... 3/10枚」）
タイムアウト（30秒）: エラー表示に切り替え
```

## 2. プライバシー / データ取り扱い方針

### 2-1. 基本原則

1. **写真は飼い主のもの**: にゃるほどは写真を「預かっている」立場。AI学習に使わない
2. **必要最小限のデータ**: 機能に必要ないデータは収集しない
3. **透明性**: 何のデータを、なぜ集めているか、いつでも説明できる状態にする
4. **削除の権利**: ユーザーがアカウント削除したら、すべてのデータを完全削除

### 2-2. 収集するデータ

| データ | 目的 | 保存場所 | 保持期間 |
|--------|------|---------|---------|
| メールアドレス | 認証 | Supabase Auth | アカウント存続中 |
| 猫の情報（名前、年齢等） | アプリ機能 | Supabase DB | アカウント存続中 |
| 写真 | アプリ機能 | Supabase Storage | アカウント存続中 |
| AI解析結果（タグ、ポーズ等） | 図鑑生成 | Supabase DB | アカウント存続中 |
| ケア記録 | アプリ機能 | Supabase DB | アカウント存続中 |
| 利用イベントログ | サービス改善 | Supabase DB | 90日後に匿名化 |
| FCMトークン | プッシュ通知 | Supabase DB | アカウント存続中 |

### 2-3. 収集しないデータ

- 位置情報（写真のEXIFから読み取る場合はユーザーに明示）
- 連絡先
- 端末の他アプリ情報
- 写真のAI学習用の二次利用

### 2-4. AI処理に関するポリシー

```
写真のAI解析について:
- 解析は OpenAI Vision API を使用します
- 写真はAPI呼び出し時にのみ送信され、OpenAI側に保存されません
  （OpenAI の API Data Usage Policy に準拠: APIデータは学習に使用されない）
- 解析結果（タグ、ポーズ分類）のみ保存します
- ユーザーは解析をオプトアウトできます（写真は保存されるがタグ付けされない）
```

### 2-5. データ削除

```
写真の削除:
- ユーザーが削除 → Supabase Storage から即座に削除
- 関連する photo_analysis_results, photo_cat_links も削除（CASCADE）

アカウント削除:
- 全写真、全記録、プロフィール、分析結果を完全削除
- 匿名化済みのイベントログは統計目的で保持
- 削除は72時間以内に完了。完了時にメール通知
- 削除後30日間はリカバリ不可であることを事前に警告
```

### 2-6. 家族共有時のプライバシー

```
- 同一 household 内のメンバーは全写真・全記録にアクセス可能
- メンバーの招待・削除は household オーナーのみ
- メンバーが退出した場合、そのメンバーがアップロードした写真は household に残る
  （共有データのため。個人アカウントのデータは保持される）
```

## 3. PWA固有の設計

### 3-1. Service Worker 戦略

現行: `public/sw.js` が `prebuild` で生成されている。
方針: **App Shell + Network First** ハイブリッド戦略

```
App Shell（キャッシュ優先）:
├── HTML シェル（layout.tsx の静的部分）
├── CSS / JS バンドル
├── フォント（Zen Maru Gothic）
├── アイコン / ロゴ
└── オフラインフォールバックページ

写真（Network First）:
├── サムネイル → キャッシュ（LRU、上限100MB）
├── フルサイズ → ネットワーク優先、キャッシュにフォールバック
└── アップロード待ち → Background Sync

APIレスポンス（Stale While Revalidate）:
├── 猫一覧 / 図鑑データ → キャッシュを先に返し、裏で更新
├── ケア記録 → キャッシュを先に返し、裏で更新
└── AI解析結果 → ネットワーク優先
```

### 3-2. オフライン対応

#### 完全オフライン時にできること

| 機能 | オフライン対応 | 方法 |
|------|-------------|------|
| 写真の閲覧（キャッシュ済み） | ✅ | Service Worker キャッシュ |
| 図鑑の閲覧（キャッシュ済み） | ✅ | React Query の staleTime + gcTime |
| 写真の撮影 | ✅ | ローカル保存→オンライン復帰時にアップロード |
| ケア記録の追加 | ✅ | localStorage に保存→オンライン復帰時に同期 |
| 写真のアップロード | ❌ → キュー | Background Sync で復帰時に自動送信 |
| AI解析 | ❌ | オンライン時のみ |
| 新しい写真のインポート | △ | 選択まではオフラインOK、アップロードはオンライン時 |

#### オフライン時のUI

```
画面上部に薄いバナー:
「オフラインです。一部の機能は次回接続時に反映されます」
色: --bg-tertiary（目立ちすぎない）
```

### 3-3. Background Sync

```javascript
// 写真アップロードの Background Sync
self.addEventListener('sync', event => {
  if (event.tag === 'photo-upload') {
    event.waitUntil(uploadPendingPhotos());
  }
  if (event.tag === 'care-log-sync') {
    event.waitUntil(syncPendingCareLogs());
  }
});
```

### 3-4. プッシュ通知（FCM経由）

```
通知の種類と頻度:
├── 週次アルバム完成 → 週1回（日曜夕方）
├── 新しい発見 → 発生時（1日最大2回）
├── 1年前の今日 → 該当日の朝
├── ケアリマインダー → ユーザー設定の時刻
└── 家族からのアクティビティ → リアルタイム（静音時間除外）

静音時間: ユーザー設定（デフォルト 22:00〜7:00）
```

### 3-5. インストールプロンプト

```
PWA インストール促進:
├── 初回訪問 → 表示しない（まず価値を体験させる）
├── 3回目のアプリ起動 → 下部バナー「ホーム画面に追加すると、もっと便利に」
├── 写真を5枚以上追加後 → 「ホーム画面に追加すると通知が届きます」
└── ユーザーが閉じたら → 30日間表示しない
```
